## Notes

Add Supabase Auth (email + password) so access is tied to a logged-in user, and
move `known_state` and `user_words` to Supabase tables keyed by `user_id` with
row-level security. Satisfies the 10xBuilder authentication requirement ("a user
who logs in and sees resources assigned to them"), which the current on-device
single-user model does not meet as written.

Decision — **hybrid data model** (chosen 2026-09-10):
- `known_state` + `user_words` → Supabase Postgres, per `user_id`, RLS-enforced.
- The typed person-description still never leaves the device (PRD NFR / test-plan
  Risk #7 preserved — it stays in React state only, no persistence, no network).
- The hard "fully usable with no network connection" NFR is relaxed to "usable
  offline after login, backed by a local cache". Login and first deck load need
  connectivity.

Foundation docs to amend as part of this change:
- `prd.md` — Access Control section (single-user/no-auth → accounts + RLS);
  NFR "no network connection" → offline-after-login; resolve Open Question #1
  (cloud sync) partially.
- `roadmap.md` — Open Roadmap Question / Parked: cloud sync now in scope for auth.
- `tech-stack.md` — add Supabase (`@supabase/supabase-js`, `expo-secure-store`
  for session storage).
- `test-plan.md` — new risk rows: (a) logged-out / expired-session user reaches
  another user's data; (b) RLS gap lets a query read across `user_id`.
- `infrastructure.md` — Supabase project as a managed backend dependency.

External setup the user must do (cannot be automated here):
- Create a Supabase project; put URL + anon key in `.env`
  (`EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`).
- Apply the SQL migration (tables + RLS policies) generated by the plan.
- Turn OFF "Confirm email" (Authentication → Sign In / Providers → Email).
  Verified via `GET /auth/v1/settings` → `mailer_autoconfirm: true`.

## Deviations from plan

- **`app.json` `web.output: "static"` → `"single"`.** `web.output: "static"`
  prerenders every route in Node at export time; `AuthProvider` in the root
  layout initialises the Supabase auth client (`_emitInitialSession`), which
  crashes the Node prerender. The app has no SEO need for SSG, so it is now a
  client SPA. The Playwright e2e target is unaffected (still `expo export` +
  static server, now a single `index.html`).
- **"Sign out" control added to `src/app/index.tsx` in Phase 1.** The plan put
  the login screen in Phase 1 but placed no sign-out affordance anywhere, so
  manual step 1.7 was unverifiable. A small "Sign out" text button was added to
  the input screen next to "Manage my cards".
- **Session storage is AsyncStorage on all platforms**, not
  `expo-secure-store` on native. SecureStore's ~2 KB per-value limit is
  unreliable for a full Supabase session without a chunking/encryption wrapper
  (out of scope). `expo-secure-store` stays installed, reserved for a hardening
  follow-up. This matches the Expo + Supabase guide's common-case pattern.
- **Test emails must use a real domain** (e.g. `@gmail.com`). Supabase's email
  validator rejects reserved TLDs like `.test` / `.example`.
